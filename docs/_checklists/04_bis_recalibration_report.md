## Диагностика: почему K_NLDR=1.0 при ρ(A)=0.70, T=30

### Деталь 1 — деторминистическая траектория без шума

```
A = [[0.0000  0.3500  0.3500]
     [0.4083  0.0000  0.3500]
     [0.2917  0.3500  0.0000]]
ρ(A) = 0.7000
```

Запуск SDE с σ=0 (чистый детерминизм), x0=[0.3, 0.3, 0.3], shock=[0.10, 0, 0]:

```
  step  energy   water   transport
     0  0.3000   0.3000  0.3000
     1  0.4204   0.3221  0.3186
     5  0.5175   0.4431  0.4200
    10  0.6869   0.6411  0.5904
    15  0.9279   0.9110  0.8267
    20  1.0000   1.0000  1.0000
```

### Деталь 2 — аналитический показатель роста

SDE: `dx = (A·x − ρ_rec·x) dt + σ·x dW`.
Линейный генератор: `A − ρ_rec·I`.

```
max Re(eig(A − ρ_rec·I)) = 0.7000 − 0.02 = 0.6800  (> 0 → неустойчивость)
Exp. growth factor over T_phys=3.0:  exp(0.68·3) = 7.69
x(0) = 0.3 → теоретический x(T) = 2.31 (clipped на 1.0)
Time-to-threshold C=0.75: ln(0.75/0.3) / 0.68 = 1.35 time units = step 13
```

Детерминистически SDE **неизбежно** достигает C=0.75 до step 14 при любом неотрицательном x0≥0.3. Стохастика (σ>0) этому только помогает.

### Деталь 3 — почему смена ρ(A) и T_steps недостаточна

Для того чтобы SDE **не** насыщался за T=30 шагов при x0=0.3 и C=0.75, нужен показатель роста λ такой что:

```
x(0)·exp(λ·T_phys) < 0.75
0.3·exp(λ·3.0) < 0.75
λ < ln(2.5)/3.0 ≈ 0.305
```

Это требует **ρ(A) < ρ_rec + 0.305 = 0.325**. То есть ρ-cap должен быть понижен до ~0.30, что даст off-diagonals ~0.15 и сделает матрицу малокаскадной (NEVA/IIM также перестанут разрешать amplitude).

Уменьшение только T_steps не спасает: время выхода x на C ≈ 13 шагов; даже T=10 даёт K_cl≈0.5 (step 13 > 10, но шум и более жёсткий shock-инициатор закрывают это). Только T ≤ 8 даст значимое рассеяние K, но такой горизонт физически нереалистичен (0.8 часа real-time при dt=0.1).

## Корень: структурная особенность SDE-формы

Текущая SDE:
```
dx_j = (Σ_i A[j,i] x_i − ρ_rec x_j) dt + σ_j x_j dW_j
```

Свойство: при ρ(A) > ρ_rec **все возмущения растут экспоненциально**. Система асимптотически неустойчива по Ляпунову (clipping на [0,1] — единственное, что её удерживает).

Это **не баг**, а структурное проектное решение модели (x — «риск-уровень», 0 — норма, 1 — отказ). Но оно означает: для разрешения severity нужно чтобы **время выхода на C было сравнимо с T_steps**, что требует либо:

1. **низкого x0** (≤0.10 вместо 0.30),
2. **высокого ρ_rec** (≥0.50 — сильная диссипация),
3. **перехода на OU-форму**: `dx = (A·x − x) dt + σ dW` (автоматический mean-reversion при ρ(A)<1), либо
4. **отказа от SDE saturation метрики** в пользу «time to cascade» как primary indicator.

Инструкция Этапа 4-bis запрещает менять что-либо кроме ρ и T — поэтому устранение неустойчивости в рамках этого промпта **невозможно**.

## Рекомендация (мнение)

Комбинация **V1 + V2** (ρ_rec=0.30–0.50, x0=0.10–0.15) даёт наибольшую вероятность получить разрешающую способность без изменения SDE-формы. Это не «лечение симптома», а калибровка ранее не обсуждённых параметров под разумный физический диапазон:
- ρ_rec=0.02 было взято произвольно как «mild mean-reversion»; в реальности рестарт ICS после stress занимает часы (0.1–0.5/час — нормальное восстановление).
- x0=0.3 — «generic operational baseline»; honestly это уже 40% пути до capacity. В реальных ICS baseline ~0.1 (системы далеко от максимальной загрузки до шока).

Альтернативно — V5 + добавление в ВКР честного обсуждения «sensitivity-режимов», где разные операторы доминируют.
